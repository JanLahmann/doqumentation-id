Membuat dan mengelola instance

Akses ke layanan IBM Quantum Platform dikendalikan oleh instance yang kamu ikuti. Pengguna bisa terdaftar di beberapa instance sekaligus.

Instance adalah server virtual (deployment Qiskit Runtime) yang mengelola eksekusi workload-mu, termasuk menjalankan program kuantum dan tugas komputasi klasik (seperti pemrosesan error mitigation). Instance diidentifikasi melalui Cloud Resource Name (CRN)-nya. CRN ini bisa digunakan saat mengirim workload dari program Qiskit-mu.

Kamu bisa melihat instance yang bisa kamu akses di dashboard, atau dengan mengklik tab "Instances" dari dashboard. Setiap instance ditampilkan beserta pengenal CRN-nya.

Kamu memerlukan instance yang berbeda untuk setiap paket layanan (seperti Open atau Pay-As-You-Go) yang kamu gunakan di setiap region yang ingin kamu pakai. Manajer akun dan siapa saja dengan izin yang cukup bisa membuat instance dan mendefinisikan konfigurasinya, seperti alokasi, batas penggunaan, komputer kuantum, dan izin pengguna.

Dashboard IBM Quantum Platform menampilkan instance yang bisa kamu akses. Tergantung aksesmu, kamu bisa melihat detail lengkap, mengedit, dan menghapus instance di halaman Instances.

Penting untuk memahami instance mana yang kamu gunakan, karena semua instance yang tidak terkait dengan Open Plan akan dikenakan biaya.

Instance Open Plan​

Pengguna Open Plan bisa menjalankan circuit kuantum di QPU terbaik di dunia secara gratis (hingga 10 menit waktu kuantum per jendela bergulir 28 hari). Penggunaan QPU bisa dipantau di halaman Platform dashboard dan Workloads.

Instance Pay-As-You-Go Plan​

Pay-As-You-Go Plan adalah paket berbayar. Untuk menggunakan paket ini, kamu harus membuat instance dan menugaskannya ke paket tersebut. Semua workload yang dikirim ke QPU menggunakan paket ini akan dikenakan biaya.

Job yang kamu jalankan dan job yang dijalankan oleh kolaborator lain di instance yang sama akan dihitung dalam penggunaan yang dilaporkan untuk instance tersebut. Kamu bisa melihat penggunaan instance di halaman Instances, atau, bagi yang memiliki wewenang yang sesuai, di halaman Analytics. Perlu diperhatikan bahwa kedua halaman tersebut mungkin menampilkan angka penggunaan yang berbeda karena halaman Instance menampilkan penggunaan dalam jendela bergulir 28 hari sebelum timestamp saat ini, sementara halaman Analytics menggunakan batas hari penuh.

Jika sebuah instance telah ditandai sebagai "limited" oleh administratormu (kamu akan melihat kolom "Remaining" di area penggunaan) dan instance tersebut melebihi alokasinya (yang ditentukan oleh administratormu) dalam jendela bergulir 28 hari, workload yang sedang aktif akan terus berjalan (termasuk session) tetapi workload yang tertunda akan tetap berada di antrean hingga ada waktu yang tersedia. Jika sebuah instance tidak dibatasi dan melebihi alokasinya, job yang dijalankan dengan instance tersebut kemungkinan akan berjalan dengan prioritas lebih rendah dan mengalami waktu antrean yang lebih lama.

Sebuah peringatan akan muncul pada penggunaan instance saat melebihi alokasinya.

Menentukan instance dalam kode-mu​

Kamu bisa menggunakan CRN atau nama instance untuk menentukan instance yang akan digunakan — baik saat menginisialisasi layanan, maupun saat mengirim workload ke QPU (misalnya, dengan `QiskitRuntimeServicee.backend()). Untuk instruksi menentukan instance dalam kode-mu, lihat Inisialisasi akun-mu.

Ketika sebuah instance dimasukkan, hanya backend dan job dari instance tersebut yang tersedia (diizinkan di Qiskit Runtime v0.40.1 dan yang lebih baru).

Jika instance tidak disertakan saat menginisialisasi layanan, semua backend dan job di semua instance dalam akunmu akan tersedia. Dalam hal ini, saat backend ditentukan, instance yang bisa mengakses backend tersebut akan ditemukan dan digunakan seperti yang dijelaskan di Pemilihan instance otomatis.

Versi yang diperlukan

Qiskit Runtime v0.40.1 atau yang lebih baru diperlukan untuk hal-hal berikut:

  • Menggunakan nama instance untuk menentukan instance
  • Tidak memasukkan instance
  • Mengatur tipe instance dan region yang diinginkan

Untuk Qiskit Runtime v0.42 atau yang lebih baru, paket gratis diprioritaskan secara default saat pemilihan instance otomatis digunakan.

Membuat instance​

Ikuti langkah-langkah berikut untuk membuat instance dan menambahkannya ke akunmu. Jika kamu adalah administrator yang perlu menyiapkan Qiskit Runtime di Cloud untuk organisasimu, lihat Merencanakan Qiskit Runtime untuk organisasi.

  1. Untuk menambahkan instance ke akunmu, pertama pastikan kamu telah memilih akun dan region yang benar di pemilih akun di header.

    • Kamu bisa memiliki (atau menjadi bagian dari) beberapa akun IBM Cloud. Jika kamu tidak melihat instance atau job yang kamu harapkan, coba akun yang berbeda.
    • Kamu bisa mengakses salah satu region menggunakan API key yang sama, tetapi kamu hanya bisa melihat dan mengakses instance yang dibuat di region tempat kamu masuk.
    • Jika kamu ingin membuat instance Open, kamu harus memilih region us-east.

    Tentang region

    Instance akan dibuat di region yang dipilih. Region ini menentukan karakteristik penting berikut:

    • QPU mana yang tersedia.
    • Di mana komputasi klasik job, seperti kompilasi, berlangsung.
    • Di mana data workflow pengguna disimpan.

    Data workflow mencakup circuit input, parameter circuit, dan hasil komputasi kuantum. Ini tidak mencakup metadata, seperti jumlah shot, ukuran circuit, atau statistik job lainnya.

    Untuk menghindari paparan data workflow pengguna ke lapisan perlindungan Distributed Denial of Service global, kamu bisa menggunakan Virtual Private Endpoints. qiskit-ibm-runtime mendukung ini melalui parameter private_endpoint.

  2. Dari panel Instances di dashboard, klik View all, atau buka halaman Instances dari menu utama.

  3. Dari halaman Instances, klik Create instance.

    • Masukkan nama dan secara opsional tambahkan tag.
    • Jika kamu memiliki akses ke lebih dari satu resource group di IBM Cloud®, kamu bisa memilih untuk mengubah resource group tempat instance ini berada. Lihat Managing resource groups dan Giving access to resources in resource groups untuk informasi lebih lanjut.

  4. Pilih paket harga yang terkait dengan instance ini (misalnya, Pay-As-You-Go). Tergantung pada paket harga yang dipilih, kamu bisa menentukan opsi lain, seperti batas biaya atau jumlah menit yang dialokasikan untuk instance ini. Perlu diperhatikan bahwa jika instance ini tidak terkait dengan paket gratis, biaya akan dikenakan saat instance ini digunakan untuk menjalankan workload.

  5. Klik Next. Daftar QPU yang bisa diakses instance ditampilkan.

    • Jika kamu ingin instance memiliki akses ke semua QPU yang terdaftar (dan semua QPU yang ditambahkan ke paket ini di masa mendatang), klik Next.
    • Jika kamu tidak menyiapkan instance open, kamu bisa menyesuaikan QPU mana yang bisa diakses dengan instance ini. Klik toggle "Customize allocated compute resources". Pilih QPU tertentu yang bisa diakses oleh instance ini, lalu klik Next.
      catatan

      Jika kamu menyesuaikan resource komputasi yang dialokasikan, QPU yang tersedia tidak akan pernah diperbarui secara otomatis, terlepas dari perubahan apa pun yang dilakukan pada paket induk. Namun, kamu bisa menambah atau menghapus QPU secara manual nantinya. Jika kamu tidak menyesuaikannya, kamu akan selalu memiliki akses ke QPU mana pun yang bisa diakses akun pada paket tersebut. Jadi jika di masa mendatang ada QPU baru yang ditambahkan ke paket, instance secara otomatis memiliki akses ke sana.

  6. Panel Access group terbuka. Grup akses "collaborators" secara otomatis dibuat untuk instance ini. Pengguna yang ditambahkan ke grup akses ini bisa menggunakan waktu yang dialokasikan untuk instance ini. Kamu bisa memodifikasi atau membuat grup akses tambahan menggunakan konsol IBM Cloud. Lihat Setting up access groups untuk petunjuknya.

  7. Klik Create instance. Kamu sekarang bisa melihat instance di halaman Instances. Jika kamu telah menyiapkan beberapa paket di akunmu, setiap jenis paket memiliki tab sendiri di tabel Instances.

Mengedit instance dan alokasinya​

Temukan instance di halaman Instances. Klik menu overflow di ujung baris instance tersebut, dan pilih Edit details.

catatan

Hanya administrator dan pemilik yang bisa mengedit instance. Lihat panduan Membuat kebijakan akses dan grup akses untuk informasi tentang menetapkan akses.

Langkah selanjutnya​

Rekomendasi

  • Mengelola pengguna.
  • Simpan kredensial login-mu
  • Inisialisasi layanan Qiskit Runtime di lingkungan Python yang terpercaya
