Kelola workflow superkomputasi quantum-centric dengan QCSC-Prefect

Perkiraan penggunaan: 30 detik waktu QPU pada prosesor IBM Quantum® Heron r2. Perkiraan ini tidak termasuk waktu antrean dan pemrosesan klasik. Waktu jalan sebenarnya bisa berbeda.

Hasil pembelajaran​

  • Telusuri workflow superkomputasi quantum-centric (QCSC) di Prefect Cloud, dengan satu task per tahap pola Qiskit.

  • Konfigurasikan workflow menurut peran, dengan parameter run di form run Prefect Cloud dan pengaturan high-performance computing (HPC) serta quantum processing unit (QPU) di blok Prefect.

  • Lanjutkan run yang gagal tanpa mengulang job QPU-nya, dan pakai ulang sampel dari satu run di run baru.

Prasyarat​

  • Siapkan QCSC-Prefect di cluster Slurm, yang menyiapkan login node Slurm, environment Python, dan kredensial IBM Quantum.

  • Sample-based quantum diagonalization dari Hamiltonian kimia, yang menjelaskan algoritmanya.

Latar belakang​

Workflow QCSC menjalankan QPU dan sistem HPC sebagai satu mesin. QCSC-Prefect menjalankan workflow QCSC di Prefect dan menjaganya tetap bisa ditelusuri, dikonfigurasi, dan dilanjutkan.

Tutorial ini mendemonstrasikan fitur-fitur ini dengan sample-based quantum diagonalization (SQD) dari molekul N2_22​. Quantum Resource Management Interface (QRMI) men-sampel circuit di dalam job Slurm. Eigensolver Fulqrum mendiagonalisasi subruang hasil sampel di job Slurm yang lebih banyak. Satu deployment Prefect Cloud menjalankan keduanya.

QCSC-Prefect juga menjalankan beban kerja QCSC besar, seperti pada proyek-proyek berikut.

  • Studi kompleks protein-ligan dengan lebih dari 12.000 atom memakai QCSC-Prefect. Studi itu men-sampel fragmen quantum-embedding pada dua prosesor IBM Quantum 156-qubit, dengan hingga 94 qubit, dan mendiagonalisasi subruang fragmen pada superkomputer Fugaku, Miyabi-G, dan ROQUO [1].

  • Studi klaster besi-belerang menjalankan workflow SQD QCSC-Prefect yang diperluas dengan 36 orbital (72 qubit) dan dimensi subruang hingga 3×10103 \times 10^{10}3×1010 pada superkomputer Fugaku, Miyabi, dan ROQUO [2].

Tantangan workflow QCSC​

Workflow SQD tipikal untuk beban kerja QCSC. QCSC-Prefect menjawab setiap tantangannya dengan satu fitur, seperti pada tabel berikut.

Setiap langkah di Pola Qiskit di QCSC-Prefect langkah demi langkah diakhiri dengan kotak yang menunjukkan bagaimana QCSC-Prefect menelusuri, mengonfigurasi, dan melanjutkan tahap itu.

Workflow yang bisa ditelusuri​

Flow Prefect adalah fungsi Python yang terdiri dari task. QCSC-Prefect menjadikan setiap tahap dari pola Qiskit (Map, Optimize, Execute, dan Postprocess) satu task. Untuk setiap run, Prefect Cloud menampilkan informasi berikut:

  • Grafik task, dengan panah di setiap tempat satu task meneruskan hasilnya ke task lain.

  • State, input, log, dan durasi tiap task, yang bisa difilter menurut tag tahap map, optimize, execute, dan post-process.

  • Artifact, yaitu tabel dan tautan yang dipublikasikan task, seperti sumber sampel atau energi tiap subruang.

Host workflow hanya mengirim dan memantau pekerjaan. Pekerjaan yang berat secara komputasi berjalan sebagai job Slurm, seperti pada gambar berikut.

Eksekusi yang bisa dilanjutkan​

Prefect menyimpan hasil tiga tahap pertama bersama flow run. Kalau task berikutnya gagal, Retry pada flow run memakai ulang hasil yang tersimpan dan hanya menjalankan yang gagal, seperti pada gambar berikut.

Run baru juga bisa memuat sampel dari run sebelumnya alih-alih men-sampel, karena tahap Execute mencatat di mana sampelnya berada.

SQD sekilas​

SQD men-sampel bitstring dari circuit local unitary cluster Jastrow (LUCJ) yang dibangun dari amplitudo coupled cluster singles and doubles (CCSD), memperbaiki bitstring yang rusak karena noise (configuration recovery), dan mendiagonalisasi Hamiltonian dalam subruang yang direntang oleh konfigurasi hasil sampel [3]. Tutorial SQD menjelaskan algoritmanya. Di QCSC-Prefect, SQD adalah flow sqd, yang punya grafik task berikut.

TahapTaskInput dari task lain
Mapcompute_molecular_integralsTidak ada
Optimizeget_lucj_paramsIntegral dari Map
Executequantum_sampling, dengan build_lucj_circuit di dalamnyaParameter LUCJ dari Optimize
Postprocesssqd_loopIntegral dari Map, dan sampel dari Execute

Saat run memakai ulang sampel, load_qrmi_result (atau load_runtime_job untuk sampel dari IBM Quantum Platform) menggantikan get_lucj_params sekaligus quantum_sampling, jadi run itu tidak punya task Optimize. Pada mode random (Quantum Source diatur ke random), tidak ada task Optimize atau Execute, dan Map langsung mengumpan sqd_loop.

Contohnya adalah N2_22​ pada panjang ikatan 1,1 A˚\AAA˚ dalam basis 6-31G, dengan dua orbital inti 1s yang dibekukan. Ini menyisakan 16 orbital spasial dengan lima elektron α\alphaα dan lima β\betaβ, yaitu circuit 32-qubit.

Persyaratan​

Untuk menjalankan sel kode notebook ini, instal paket-paket berikut di kernel notebook.

  • Qiskit SDK v2.0 atau lebih baru, dengan dukungan visualisasi.

  • Qiskit Runtime v0.40 atau lebih baru (pip install qiskit-ibm-runtime).

  • Addon Qiskit SQD v0.14 atau lebih baru (pip install qiskit-addon-sqd).

  • ffsim v0.0.75 atau lebih baru (pip install ffsim).

  • Fulqrum v1.0 atau lebih baru (lihat panduan instalasi Fulqrum).

Langkah 3 notebook ini men-sampel dengan Qiskit Runtime, jadi butuh akun IBM Quantum yang tersimpan di komputer yang menjalankan notebook, seperti dijelaskan di Simpan kredensial login kamu.

catatan

Workflow QCSC-Prefect berjalan di cluster yang dikelola Slurm, bukan di notebook ini. Sebelum menjalankannya, selesaikan Siapkan QCSC-Prefect di cluster Slurm, yang menyediakan item-item berikut.

  • Checkout QCSC-Prefect di $QCSC_PREFECT (~/qcsc-prefect) dan direktori kerja di $QCSC_WORK_DIR (/shared/work/qcsc-prefect), keduanya di storage yang dipakai bersama oleh node komputasi.

  • Di login node Slurm, yaitu host workflow, environment ~/venv/qcsc-host dengan paket QCSC-Prefect, dan login Prefect Cloud.

  • Kredensial IBM Quantum, yang disimpan dengan qcsc-qrmi login, dan blok qrmi-runtime, di cluster dengan QRMI dan plugin SPANK-nya.

  • Di node komputasi, environment ~/venv/qcsc-node dengan QRMI, task_runner-nya, dan qcsc-prefect-qiskit.

Jalankan langkah-langkah berikut satu kali. Setiap langkah menyebut node tempat langkah itu berjalan.

Instal workflow SQD di host workflow​

Atur variabel dari panduan setup, aktifkan ~/venv/qcsc-host, lalu instal workflow SQD dan integrasi Fulqrum.

# Run in a terminal on the workflow host.
# Optional if your ~/.bashrc sets the two variables
export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR="/shared/work/qcsc-prefect"

source ~/venv/qcsc-host/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e packages/qcsc-prefect-fulqrum
uv pip install -e algorithms/qcsc_workflow_utility
uv pip install -e algorithms/open_loop/sqd
which sqd-create-blocks sqd-deploy

Instal solver Fulqrum di node komputasi​

Buka shell di node komputasi. srun meneruskan variabel dari shell host workflow ke node komputasi.

# Run in a terminal on the workflow host.
srun -N1 --pty bash

Worker QRMI men-transpile circuit di node komputasi dengan hook transpilasi SQD, yang hanya meng-import Qiskit. Tambahkan hook itu ke ~/venv/qcsc-node dan periksa import-nya. Perintah python tidak mencetak apa-apa kalau import-nya berhasil.

# Run in the shell on the compute node.
source ~/venv/qcsc-node/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e algorithms/open_loop/sqd
python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker, sqd_common.transpile"

Build Fulqrum dan qcsc-fulqrum-solve ke environment mereka sendiri, packages/qcsc-prefect-fulqrum/native/fulqrum. Build ini butuh compiler C++ dengan OpenMP. FULQRUM_WITH_PRIMME=1 juga mem-build eigensolver PRIMME, yang butuh compiler C, header Python, pkg-config, dan library BLAS dan LAPACK dengan file .pc.

# Run in the shell on the compute node.
cd "$QCSC_PREFECT"
FULQRUM_WITH_PRIMME=1 bash packages/qcsc-prefect-fulqrum/native/build_fulqrum.sh
realpath packages/qcsc-prefect-fulqrum/native/fulqrum/bin/qcsc-fulqrum-solve
exit

Catat path yang dicetak, karena blok solver menunjuk ke sana. exit kembali ke host workflow. Untuk opsi build, lihat integrasi Fulqrum.

Perhatikan poin-poin berikut saat mengedit file.

  • Tulis path secara lengkap, karena file tidak mengekspansi variabel environment. Karakter ~ bisa dipakai. Letakkan setiap key tingkat atas, seperti python_executable, sebelum header tabel pertama.

  • Tabel [qrmi] tidak perlu diubah, karena blok qrmi-runtime menyediakan instance dan QPU. Setel resource hanya untuk menimpa backend. Kredensial tetap ada di qrmi_config.json, bukan di file ini.

  • Profil slurm memuat pengaturan scheduler dan resource dari cluster Slurm generik, dan key apa pun di file kamu menimpanya. Tabel [sqd_advanced] yang dikomentari menyetel blok sqd-advanced-settings, tabel [advanced] yang dikomentari menyetel nama blok dan timeout, dan tabel tiap solver memuat tuning-nya. Untuk memilih node, rank, dan thread dari job solver, lihat Atur ukuran diagonalisasi SQD untuk resource HPC kamu.

  • Job QRMI dan setiap job solver punya walltime 12 jam (#SBATCH --time), dan flow menunggu hingga 13 jam (timeout_seconds = 46800) untuk setiap job. Untuk mengubah walltime, setel walltime di bagian atas file untuk job solver, atau di tabel [qrmi] untuk job QRMI, misalnya walltime = "02:00:00". Walltime yang lebih pendek bisa mulai lebih cepat di cluster yang sibuk.

Deploy workflow di workflow host​

sqd-deploy menyajikan flow dari workflow host dan mengambil run yang kamu mulai di Prefect Cloud, jadi biarkan terminal tetap terbuka selama workflow berjalan. Perintah berikut juga menulis output ke file log baru di $QCSC_WORK_DIR/logs/deploy setiap kali dimulai, dengan nama sesuai waktu mulai dalam UTC, misalnya sqd-deploy-20261109T051530Z.log.

# Run in a terminal on the workflow host.
mkdir -p "$QCSC_WORK_DIR/logs/deploy"
sqd-deploy 2>&1 | tee "$QCSC_WORK_DIR/logs/deploy/sqd-deploy-$(date -u +%Y%m%dT%H%M%SZ).log"

Saat output menunjukkan bahwa flow sqd sedang disajikan, deployment muncul di Prefect Cloud di bawah Deployments. Tekan Ctrl+C untuk berhenti menyajikan.

Qiskit Pattern di QCSC-Prefect langkah demi langkah​

Langkah-langkah berikut menghitung empat tahap di notebook ini dengan PySCF, ffsim, Qiskit, Qiskit Runtime, dan qiskit-addon-sqd, tanpa Prefect. Lihat tutorial SQD untuk detail setiap komputasi.

Langkah 1: Petakan input klasik ke masalah kuantum​

Tahap Map, yaitu task compute_molecular_integrals di workflow, mengubah molekul menjadi input untuk semua tahap berikutnya. Restricted Hartree-Fock (RHF) menghasilkan orbital molekul, dan integral active-space mengabaikan dua inti 1s yang dibekukan. CCSD menghasilkan amplitudo t2t_2t2​ untuk ansatz, dan matriks densitasnya menghasilkan okupansi orbital yang memulai configuration recovery. CCSD berulang sebanyak CCSD_MAXITER kali, setiap kali dari amplitudo sebelumnya, sehingga hasilnya tidak bergantung pada riwayat DIIS dari iterasi pertama. Notebook ini memakai 4 iterasi, dan workflow memakai 10.

ATOM = "N 0 0 0; N 0 0 1.1"
BASIS = "6-31g"
N_FROZEN = 2
CCSD_MAXITER = 4

mol = pyscf.gto.M(atom=ATOM, basis=BASIS, symmetry=False, verbose=0)
mf = scf.RHF(mol).run()
norb = mol.nao_nr() - N_FROZEN
nelec = (mol.nelec[0] - N_FROZEN, mol.nelec[1] - N_FROZEN)

# Active-space Hamiltonian with the 1s cores frozen
cas = mcscf.CASCI(mf, ncas=norb, nelecas=nelec)
one_body_tensor, core_energy = cas.get_h1eff()
two_body_tensor = ao2mo.restore(1, cas.get_h2eff(), norb)

# CCSD, iterated from the previous amplitudes
ccsd = cc.CCSD(mf, frozen=N_FROZEN)
eris = ccsd.ao2mo()
ccsd.kernel(eris=eris)
for _ in range(CCSD_MAXITER - 1):
    ccsd.kernel(ccsd.t1, ccsd.t2, eris=eris)
t2 = ccsd.t2

occupancies = np.diag(ccsd.make_rdm1())[N_FROZEN:] / 2
initial_occupancies = (occupancies, occupancies)

print(f"norb = {norb}, nelec = {nelec}")
print(f"E(RHF)  = {mf.e_tot:.8f} Ha")
print(f"E(CCSD) = {ccsd.e_tot:.8f} Ha")
norb = 16, nelec = (5, 5)
E(RHF)  = -108.86761837 Ha
E(CCSD) = -109.09392115 Ha

Langkah 2: Optimalkan masalah untuk eksekusi di hardware kuantum​

Tahap Optimize, yaitu task get_lucj_params di workflow, menyesuaikan ansatz dengan QPU sebelum circuit apa pun ada. ffsim membangun operator LUCJ dari t2t_2t2​ hanya dengan interaksi yang bisa dijalankan lattice heavy-hex tanpa SWAP gate. Interaksi ini adalah pasangan spin sama dari orbital bertetangga dan pasangan spin berlawanan pada setiap orbital keempat, paling banyak lima pada prosesor heavy-hex (Heron). Setelah itu ffsim mengompresi operator (optimize=True, aktif secara default di workflow) supaya satu layer mereproduksi t2t_2t2​ dengan lebih akurat.

N_REPS = 1

pairs_aa = [(p, p + 1) for p in range(norb - 1)]
pairs_ab = [(p, p) for p in range(0, norb, 4)][:5]

lucj_op = ffsim.UCJOpSpinBalanced.from_t_amplitudes(
    t2,
    n_reps=N_REPS,
    interaction_pairs=(pairs_aa, pairs_ab),
    optimize=True,
    options={"maxiter": 50},
)
n_params = ffsim.UCJOpSpinBalanced.n_params(
    norb, N_REPS, interaction_pairs=(pairs_aa, pairs_ab)
)

print(f"Opposite-spin pairs: {pairs_ab}")
print(f"Ansatz parameters: {n_params}")
Opposite-spin pairs: [(0, 0), (4, 4), (8, 8), (12, 12)]

Cara QCSC-Prefect mengelola langkah ini

Trace: Task get_lucj_params punya tag optimize. Hasilnya membawa semua yang dibutuhkan circuit, jadi satu panah mengarah dari sana ke quantum_sampling.

Configure: Grup Circuit di form run mengatur layer LUCJ, kompresi beserta batas iterasinya, dan QPU Topology (heavy-hex atau square), yang menentukan pasangan interaksi. Block sqd-advanced-settings menyimpan reset mitigation dan pengaturan transpiler (tingkat optimisasi dan pencarian layout SABRE) yang dipakai tahap Execute.

Resume: Hasilnya disimpan secara persisten (compressed/pickle), jadi kompresi yang lama hanya berjalan sekali, bahkan kalau kamu me-retry run.

Langkah 3: Eksekusi memakai primitive Qiskit​

Tahap Execute, yaitu task quantum_sampling di workflow, membangun circuit (state Hartree-Fock, operator LUCJ, dan pengukuran), mentranspilasinya untuk QPU, lalu men-sample-nya. Pass PRE_INIT dari ffsim berjalan lebih dulu di transpiler dan mengubah gate ffsim menjadi urutan native gate yang efisien. Notebook ini melakukan sampling dengan Qiskit Runtime di ibm_fez. Ganti ibm_fez dengan backend yang bisa dipakai instance kamu. Workflow melakukan sampling lewat QRMI, di dalam job Slurm yang menahan QPU.

def correct_electron_fraction(bool_array):
    """Fraction of the bitstrings with the correct numbers of alpha and beta electrons."""
    # The right half of each bitstring is alpha, the left half is beta.
    n_alpha, n_beta = nelec
    valid = (bool_array[:, norb:].sum(axis=1) == n_alpha) & (
        bool_array[:, :norb].sum(axis=1) == n_beta
    )
    return valid.mean()

Cara QCSC-Prefect mengelola langkah ini

Trace: Task quantum_sampling punya tag execute, dan task build_lucj_circuit berjalan di dalamnya. Workflow host menyiapkan circuit dan mengirim job Slurm yang meminta QPU. Di compute node, plugin SPANK membuka session QPU, dan worker QRMI mentranspilasi serta men-sample circuit. Log task menampilkan walltime job Slurm, kedalaman dua-qubit dari circuit hasil transpilasi, dan, saat sampling selesai, ID job IBM Quantum dan waktu eksekusi QPU.

Configure: Grup Sampling di form run mengatur jumlah shot dan sumber sample, yaitu block qrmi-runtime, job dari run sebelumnya, atau bitstring acak. Block QRMI menyimpan di mana dan bagaimana job sampler berjalan, dan kredensial tetap berada di cluster.

Resume: Sample disimpan secara persisten (compressed/pickle), jadi Retry tidak mengirim job QPU baru. Artifact sqd-sampling-source mencatat di mana sample berada, jadi run baru bisa memakainya kembali, seperti di Opsional: lanjutkan dan pakai ulang workflow.

Kenapa Execute membangun dan mentranspilasi circuit

Worker QRMI mentranspilasi circuit di compute node terhadap Target QPU saat ini, jadi QRMI Runtime yang memegang transpilasi. Pembagian ini mempersiapkan sistem QCSC fault-tolerant, di mana transpilasi circuit koreksi error quantum low-density parity-check (LDPC) adalah beban kerja yang berat. Workflow meng-cache parameter circuit, bukan circuit-nya. Map dan Optimize merancang circuit. Map menghitung amplitudo CCSD, dan Optimize mengompresi operator LUCJ dengan ffsim.UCJOpSpinBalanced.from_t_amplitudes(optimize=True), yang bisa memakan waktu lebih lama daripada transpilasi untuk QPU saat ini. build_lucj_circuit dan transpiler hanya meng-encode parameter ini ke circuit ISA. Pembagian ini berbeda dari Qiskit pattern konvensional, dan menunjukkan seperti apa Qiskit pattern di sistem QCSC.

Langkah 4: Postprocess dan kembalikan hasil dalam format klasik yang diinginkan​

Tahap Postprocess, yaitu task sqd_loop di workflow, menjalankan configuration recovery yang self-consistent. Setiap putaran mengoreksi bitstring hasil sample dengan okupansi orbital saat ini, mendiagonalisasi Hamiltonian di beberapa batch konfigurasi, lalu memperbarui okupansi dari hasil terbaik. Cell berikut menjalankan diagonalize_fermionic_hamiltonian pada kedua set sample dengan pengaturan yang sama. Dimensi subruang adalah 1.000.000 determinan milik workflow (1.000 string per spin). Notebook memakai dua batch per putaran dan sepuluh putaran, sedangkan workflow memakai empat batch dan lima putaran. Seperti di workflow, Fulqrum mendiagonalisasi setiap subruang. sci_solver_from_integrals membangun Hamiltonian Fulqrum sekali dan mengembalikan sci_solver yang dipanggil fungsi untuk setiap batch. Sebuah TrimPolicy, seperti di tutorial SQD, menggabungkan string terberat dari batch ke dalam satu subruang dan mendiagonalisasinya. Dari string di atas carryover_threshold, policy ini menyimpan setengah yang terberat (carryover_ratio=0.5) untuk putaran berikutnya, seperti Carryover Fraction di workflow.

SUBSPACE_DIM = 1_000_000
NUM_BATCHES = 2
MAX_ITERATIONS = 10

policy = TrimPolicy(
    trim_ratio=0.8,
    carryover_threshold=1e-4,
    carryover_ratio=0.5,
)
sci_solver = sci_solver_from_integrals(one_body_tensor, two_body_tensor)

def run_sqd(bool_array, label):
    """Run SQD on the samples, and return the final energy and the energy of each round."""
    round_energies = []

    def callback(results):
        round_energies.append(
            min(result.energy for result in results) + core_energy
        )
        print(
            f"{label}, round {len(round_energies)}: {round_energies[-1]:.8f} Ha"
        )

    result = diagonalize_fermionic_hamiltonian(
        one_body_tensor,
        two_body_tensor,
        bool_array,
        samples_per_batch=1000,
        norb=norb,
        nelec=nelec,
        num_batches=NUM_BATCHES,
        max_iterations=MAX_ITERATIONS,
        policy=policy,
        sci_solver=sci_solver,
        symmetrize_spin=True,
        max_dim=int(np.sqrt(SUBSPACE_DIM)),
        initial_occupancies=initial_occupancies,
        callback=callback,
        seed=np.random.default_rng(24),
    )
    return result.energy + core_energy, round_energies

    random_bool_array, "Random samples"
)

Cara QCSC-Prefect mengelola langkah ini

Trace: Task sqd_loop punya tag post-process. Task ini menerima sample dan integral, jadi grafik menampilkan dua panah masuk ke sana. Setiap batch adalah satu panggilan FulqrumSolverJob, yaitu task solve_eigenstate yang mengirim satu job Slurm yang menjalankan Fulqrum. Batch dalam satu putaran berjalan bersamaan di compute node. Artifact sqd-configuration-recovery mencantumkan energi dan dimensi setiap subruang di setiap putaran.

Configure: Grup SQD di form run mengatur dimensi subruang, jumlah batch, dan jumlah putaran. Solver Block Override (solver_block_ref) di form run menggantikan Solver Block dari sqd-advanced-settings untuk satu run, misalnya dengan block DICE atau SBD. Eigensolver (PRIMME), thread, dan walltime ada di block sqd-fulqrum-solver dan execution profile-nya. Flow memuat solver block sebelum tahap apa pun, jadi nama block yang salah menggagalkan run sebelum memakai QPU.

Resume: sqd_loop tidak di-cache, tapi menyimpan checkpoint setelah setiap putaran, di sqd_checkpoints/<flow run id>/ckpt_t00_w0.npz di bawah work_dir milik solver. Checkpoint berisi okupansi yang menjadi seed putaran berikutnya dan energi terbaik sejauh ini. Pada Retry, sqd_loop melanjutkan setelah putaran terakhir yang selesai, dengan block saat ini.

Opsional: lanjutkan dan pakai ulang workflow​

Retry run yang gagal, dan pakai ulang sample-nya​

Retry: Misalkan, di run dengan Max Iteration diatur ke 10, sebuah job solver mencapai walltime-nya di putaran 5 dan sqd_loop gagal. Naikkan walltime di block exec-sqd-fulqrum-slurm di bawah Blocks, lalu pilih Retry pada flow run yang gagal. Run yang di-retry memuat hasil tersimpan dari tiga tahap pertama dan tidak mengirim job QPU. Run ini hanya menjalankan sqd_loop lagi, dengan walltime baru, dan mulai di putaran 5 dari checkpoint putaran 4. Lognya menampilkan [ckpt] RESUME from …: completed 4 step(s), lalu SQD iteration 5/10, seperti pada gambar berikut.

Reuse: Run baru menghitung ulang semuanya kecuali kamu mengarahkannya ke sample sebelumnya. Untuk mencoba dimensi subruang lain dengan sample yang sama, mulai custom run dengan parameter yang sama, atur Load from QRMI Job Directory (qrmi_result_dir) ke direktori kerja di artifact sqd-sampling-source dari run pertama, lalu ubah Subspace Dimension. Run baru menggantikan get_lucj_params dan quantum_sampling dengan load_qrmi_result, yang membaca sample dan tidak mengirim apa pun ke QPU. Reset Mitigation di sqd-advanced-settings harus sama dengan run pertama, karena proses reload menerapkannya. Untuk sample yang diambil lewat IQP, atur Load from Qiskit Runtime Job ID (qiskit_runtime_job_id) sebagai gantinya, dan tahapnya adalah load_runtime_job. Tahap ini membaca job dengan kredensial dari block QuantumRuntime prefect-qiskit yang disebut di Quantum Runtime Block (reload) (ibm-runner secara default). Buat block itu sekali dengan prefect block create quantum-runtime.

Lanjutkan recovery dengan lebih banyak putaran: Mulai custom run dengan parameter yang sama, atur Resume from Checkpoint (resume_checkpoint) ke path di artifact sqd-checkpoint dari run pertama, lalu naikkan Max Iteration. Run baru melanjutkan setelah putaran yang sudah selesai, dari okupansi dan energi terbaik yang tersimpan. Misalnya, checkpoint dengan 32 dari 100 putaran selesai dan Max Iteration diatur ke 200 melanjutkan di putaran 33/200. Run baru membaca checkpoint itu dan menulis checkpoint-nya sendiri, dan aturan berikut berlaku.

  • Sample, molekul, Subspace Dimension, Batch Number, dan tipe solver (bagian fulqrum_solver_job dari solver block) harus sama dengan run pertama, jadi pakai ulang sample-nya seperti di Reuse.

  • Nama dan pengaturan job dari solver block, seperti walltime-nya, boleh berubah.

  • Kalau ada pengaturan yang harus sama tapi berbeda, run gagal sebelum job solver apa pun dan menyebutkan perbedaannya.
